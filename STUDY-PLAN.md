# 24-Month Study Plan

Designed around approximately six focused hours per day. Treat the month ranges as a sequence, not a deadline: extend a phase when its exit criteria are not met.

| Months | Main focus | Exit evidence |
|---|---|---|
| 1–2 | Python, C++, Git, Linux, testing | Tested CLI application and comfortable tooling |
| 3–4 | Linear algebra, calculus, probability, statistics | NumPy implementations and derivations |
| 5–6 | DSA, OS, architecture, networking, databases | DSA practice plus systems/database project |
| 7–8 | NumPy, Pandas, visualization, SQL, data pipelines | Reproducible data analysis pipeline |
| 9–10 | Classical ML and evaluation | End-to-end tabular ML project |
| 11–12 | Neural networks and PyTorch | Train, debug, and profile deep learning models |
| 13–14 | CNNs, NLP, attention, Transformers | Image project and tiny Transformer |
| 15–16 | LLMs, fine-tuning, RAG, agents, evaluation | Measured RAG/LLM application |
| 17–18 | GPU architecture, CUDA, Triton, inference | Kernel benchmark and model-serving benchmark |
| 19–20 | Backend, distributed systems, MLOps, deployment | Production-style model service |
| 21–22 | Research methods and specialization | Paper reproduction and technical report |
| 23–24 | Capstones, open source, interviews | Portfolio, contributions, interview readiness |

## Daily allocation (6 hours)
| Activity | Time |
|---|---:|
| Core theory / lectures / reading | 1 h 30 min |
| Mathematics and derivations | 1 h |
| Coding and implementation | 1 h 30 min |
| DSA / problem solving | 45 min |
| Project / experiment | 1 h |
| Review, notes, and technical writing | 15 min |

Adjust the math and DSA blocks as the phase changes. During systems-heavy months, shift some math time to operating systems, networking, and performance experiments.

## Weekly operating cycle
- **Day 1–4:** learn one concept cluster, solve exercises, implement.
- **Day 5:** integrate concepts into a small assignment.
- **Day 6:** project work, benchmarking, debugging, or paper reading.
- **Day 7:** review, write a concise summary, assess gaps, and plan the next week.

## Weekly review checklist
- Can I explain this week's central ideas without looking?
- Did I write code, not just watch content?
- Did I test edge cases and inspect failures?
- Can I explain the assumptions behind my metrics?
- Did I record what did not work and why?
- What prerequisite is still weak?

## Progress rule
Do not advance based only on time spent. Advance when you can explain the topic, solve representative problems, implement a working version, and assess its limitations. Revisit earlier material when a later project exposes a gap.
